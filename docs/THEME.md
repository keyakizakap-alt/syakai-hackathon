# テーマとの接続

テーマ：**「推し活 × 国境 — ファンダムの熱量は、無血の動員力になるか」**

この文書は、ニュアンス税関がテーマの**問いそのもの**にどう答えるかを明文化する。
「推し活に関係あるツールです」で終わらせず、テーマが立てた問いの
どの部分を担うのかを、自プロジェクトの調査結果に接続して示す。

---

## 1. テーマの問いを分解する

「熱量は**無血の**動員力になるか」という問いには、実は3つの主張が畳み込まれている。

| 要素 | 問い |
|---|---|
| 熱量 | ファンダムには十分な熱量があるか → **ある**（前提として自明） |
| 動員力 | 熱量は国境を越えて動員に変換されるか → **ここが壊れている** |
| 無血 | その動員は誰も傷つけずに成立するか → **ここも壊れている** |

このプロダクトは1番目には手を出さない。熱量を煽るのは危険だし、そもそも足りている。
**2番目と3番目が同時に壊れている一点**を扱う。

---

## 2. 自プロジェクトの調査が特定した「壊れる場所」

[非暴力動員デザイナーのレポート](./ideas/agents/05-nonviolent-mobilization.md)は、
実在のファンダム型動員（K-POPファンダムのBLM寄付リレー、ミルクティー同盟、
クラウド翻訳、バイコット消費）を分解し、**成立に必要な5条件**を導出している。
1つでも欠けると熱量は動員に変換されない。

| 条件 | 内容 | 国境を越えるとき |
|---|---|---|
| C1 焦点 | 旗印が「推し」として人格化されている | 国境で壊れない（推しは共通） |
| C2 作法 | 既存の集合行動プロトコルを転用できる | 国境で壊れない（作法は輸出される） |
| C3 計器 | 集合的達成が即時に数値で返る | 国境で壊れない（数字に言語はない） |
| **C4 橋** | **言語・時差を越える中継層がある** | **← ここが壊れる** |
| **C5 制動** | **「推しの名を汚さない」評判ステークが効く** | **← ここも壊れる** |

C1〜C3は国境を越えても生き残る。**壊れるのはC4とC5だけ**である。
そしてニュアンス税関は、この2つだけを対象にしている。

### C4「橋」が壊れる理由 ＝ 機械翻訳が熱量そのものを破壊する

レポートは「国境を越える動員は必ず翻訳する人が支えている」と書いている。
その人手を機械翻訳で代替しようとすると、**熱量が伝わらないどころか反転する**。

> 「かわいすぎて死んだ 💀」→ *"so cute I died 💀"* → 英語圏で**脅迫**として着弾

熱量の最上級表現が、受信側で最も敵対的な表現に変換される。
これは「翻訳が下手」なのではなく、**極性という次元が構造的に保存されない**という
機械翻訳の性質である。橋を架けたつもりが、橋が熱量を反転させる装置になっている。

計測: [`docs/BENCHMARK.md`](./BENCHMARK.md) の「辞書だけで届く範囲」節。
規範に関わるケースの一部は用語集に一度もヒットせず、規則ベースでは手がかりがゼロになる。

### C5「制動」が壊れる理由 ＝ 見えない加害には自制が効かない

レポートは制動の正体を「推しの名を汚さないという評判ステーク」だと特定している。
これは**自分の行為が加害だと認識できる限りにおいて**機能するブレーキである。

越境時の炎上の大半は、悪意ではなく**誤読**で起きる。
発信者は自分が何を踏んだか分からないまま、推しの名を汚す結果になる。
認識できない加害に対して、評判ステークによる自制は原理的に効かない。

これが「**無血**」が壊れる瞬間である。ファンダム動員が有血化するのは、
たいてい誰かが攻撃を意図したときではなく、**熱量が誤訳されて着弾したとき**だ。

## 3. このプロダクトが担う位置

```
C1 焦点  ─┐
C2 作法  ─┼─ 国境を越えても生き残る（このプロダクトは触らない）
C3 計器  ─┘

C4 橋    ─┐
          ├─ ニュアンス税関が担当する
C5 制動  ─┘
```

| 機能 | 担う条件 | 何をするか |
|---|---|---|
| **出国審査**（発信前チェック） | C5 制動 | 認識できない加害を、発信前に**認識可能にする**。ブレーキを踏めるようにする |
| **入国審査**（受信フィルタ） | C4 橋 | 警告が国境で失効する問題を埋め、受信側が安全に橋を渡れるようにする |

重要なのは、これが**動員を起こすツールではない**こと。
動員の前提条件（橋と制動）を整えるインフラである。
熱量を煽らず、動員を最適化せず、ただ**熱量が国境で反転しないようにする**。

## 4. なぜ「検閲」ではないのか

C5「制動」を強化するツールは、設計を誤ると容易に検閲装置になる。
このプロダクトが検閲でないことは、以下の設計上の制約で担保している。

- **削除も通報もしない。** 判定は発信者本人にだけ返る。第三者に通知しない
- **個人アカウントの分析・スコアリングをしない。** 対象は常に「一つの文」であって人ではない
- **説教しない。** 「あなたは検閲官ではなく通訳者である」をプロンプト制約として明示
  （[`lib/prompts.ts`](../lib/prompts.ts) の `TONE_RULE`）
- **どの文化も「正しい」と判定しない。** 双方の前提の違いだけを述べる

つまり返すのは判決ではなく**着弾予測**である。
それを見てどうするかは発信者が決める。制動をかけるのは常に本人。

## 5. 2つのゲートを通った唯一の領域

[選定過程](./ideas/README.md)では、評価軸を5回改訂し、最後に2つのゲートを課した。

- **テーマ適合ゲート**：推しを取り除いてプロダクトが成立するなら、このテーマの案ではない
- **AI依存ゲート**：AIを取り除いて成立するなら、AIプロダクトではない

この2つは通常トレードオフになる（推しに深く食い込む案はAIが不要で、AIが本体の案は推しが薄い）。
両方を同時に通った唯一の領域が**ファンダム語彙・規範の越境写像**だった。

### 推しを取り除くと何が残らないか

競争力の実体は[文化規範カード](../lib/norms.ts)（4文化 × 12項目）と
[ファンダム語彙集](../lib/glossary.ts)という知識資産にある。
その中身は「尊い」「地雷」「解釈違い」「同担拒否」「지뢰」「雷点」「awsl」——
**ファンダム規範そのもの**である。

一般企業向けの翻訳チェッカーは「同担拒否」を知る必要がない。
推しを取り除くと、この知識資産がまるごとゼロになり、プロダクトは何も残らない。

### AIを取り除くと何が残らないか

規則ベースで代替できない処理に絞ってある。実測値は
[`docs/BENCHMARK.md`](./BENCHMARK.md) にあり、要点は以下。

- **1対Nの条件付きタグ写像**：「地雷」は文脈により squick / NOTP / hard no のどれにもなる。
  辞書では作れない（新語が無限に生まれ、意味が前後のタグ列に依存する）
- **言語を跨いだ同義概念の接続**：「閉じ込められる」という宣言と、
  「監禁」「监禁」「감금」「囚われた」という作品側の表記の間に、
  **共有する部分文字列が一つも存在しない**。文字列一致では原理的に到達できない
- **文脈依存の極性判定**：「無理」は文脈次第で最上級の肯定にも本当の拒絶にもなる。
  辞書に極性を書き込んでも、どちらとして読むかは書けない

計測結果として、既存のタグブロック機能に相当するベースラインは
**遮断すべき作品の88.2%を取りこぼす**。あらすじ全文検索まで許した強いベースラインでも
76.5%を取りこぼし、しかも過剰遮断が3倍に増える。

## 6. 主張の検証状況

誠実に区別しておく。

| 主張 | 検証状況 |
|---|---|
| 文字列一致ベースラインが大半を取りこぼす | **実測済み**（`npm run eval`、APIキー不要で再現可能） |
| 辞書ベースでは手がかりがゼロになるケースがある | **実測済み**（同上） |
| 安全側フェイルセーフが機能する | **テスト済み**（`npm test`、14件） |
| 実モデルがベースラインを上回る | **未計測**（`OPENROUTER_API_KEY` 設定後に `npm run eval:live`） |
| 実運用のファンに効果がある | **未検証**（ユーザーテスト未実施） |

3行目までは今すぐ再現できる。4行目はキーがあれば1コマンドで埋まる。
5行目は本来ハッカソンの範囲を超えるが、埋まっていないことは明示しておく。
