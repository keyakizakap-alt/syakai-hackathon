# エージェント #9「言語・文化翻訳のAIデザイナー」

> レンズ：「国境」を言語・文化の壁として捉える。オタク用語やスラングは機械翻訳で壊滅し、ファンダム固有の規範も国ごとに違い、それが越境ファンダムの衝突を生む。

## 前半：機械翻訳が壊す「推し活表現」8選

> 原文 → よくある誤訳 → 本来の意味／壊れるもの

### 1. 尊い（日本語）
- **誤訳**: "precious" / "noble" / "sacred"
- **本来**: 美しさに打ちのめされ、**言語処理が破綻したときに漏れる悲鳴**。褒め言葉ではなく感嘆の絶叫。英語圏の等価物は "I'm not okay" / "they're so precious I'm sobbing" に近い
- **壊れるもの**: 「形容詞」に落とされることで**発話の身体性（叫び）**が消える。真顔で "noble" と訳された投稿は宗教的な賛美に見える

### 2. 担降り／同担拒否（日本語）
- **誤訳**: "getting off the person in charge" / "refusing the same charge"
- **本来**: 担降り＝応援対象をグループ内の別メンバーに変えること（＋その罪悪感の文化）。同担拒否＝同じ推しを応援する他ファンとの交流を望まない立場表明
- **壊れるもの**: 語義以前に**規範そのものが翻訳不能**。K-popの "bias / bias wrecker" は担降りに罪悪感がなくむしろネタとして楽しむ。西欧圏には「同担拒否」に相当する概念自体がほぼ無く、**「排他的で感じ悪い人」と誤認されて国際的な衝突の火種になる**

### 3. 地雷（日本語）
- **誤訳**: "landmine"
- **本来**: 二義。(a) 見ると精神的ダメージを受ける、受け入れられない要素（地雷CP／地雷ジャンル）。(b) 「地雷系」＝ファッション／情緒不安定な振る舞いの美学ジャンル
- **壊れるもの**: 英語圏の等価概念は "squick" / "NOTP" / "hard no"（(a)）と "menhera aesthetic"（(b)）で**まったく別語**。一語に潰されると、(a)の意味で書かれた警告文が(b)と読まれ、**警告として機能しなくなる＝実害**

### 4. しんどい／無理／死ぬ（日本語）
- **誤訳**: "I'm exhausted" / "It's impossible" / "I want to die"
- **本来**: すべて**最上級のポジティブ**。「良すぎて心臓と情緒が耐えられない」
- **壊れるもの**: **極性が反転する**。海外ファンが「日本のファンがカムバックに失望している」と誤読して心配ツイートが飛び交う珍事が定期的に起きる。翻訳エンジンにとって最も危険なクラス

### 5. 解釈違い（日本語・二次創作圏）
- **誤訳**: "misinterpretation" / "wrong interpretation"
- **本来**: 「**どちらも正しいが、自分の解釈とは異なる**」。相手を非難しないために発明された、極めて高度な衝突回避語彙
- **壊れるもの**: "wrong" と訳された瞬間に**衝突回避語が衝突誘発語に反転する**。日本の同人文化が数十年かけて磨いた社会技術が、翻訳一発で消える

### 6. comeback / stan / delulu（英語K-popファンダム）
- **誤訳**: comeback →「復帰」「返り咲き」、stan →「熱狂的支持者（ストーカー語感）」、delulu →「妄想（病理的）」
- **本来**: comeback＝**単なる新譜リリース活動期**（休止も引退もしていない）。stan＝ニュートラルな「ガチ勢」。delulu＝**自嘲を含んだ愛のある自虐**
- **壊れるもの**: 「復帰」と訳されたことで「え、活動休止してたの？」というデマが日本語圏に流れる。deluluを病理語に訳すと**自虐が侮辱に変わる**

### 7. 영업（ヨンオプ／韓国）・awsl・墙头（中国）
- **誤訳**: 영업 → "sales"、awsl → ローマ字のまま放置、墙头 → "wall top"
- **本来**: 영업＝**布教・沼への勧誘**。awsl＝「啊我死了」＝可愛すぎて死んだ（＝「尊い」の中国語版）。墙头＝**あちこちに推しがいて心が移ろう状態**
- **壊れるもの**: 中韓→日、中韓→英の経路は**英語ピボット翻訳**を通ることが多く二重に壊れる。「営業」と訳された布教ツイートは**ステマ疑惑**を生む

### 8. 絵文字・顔文字・記号（w／草／💀／🙏／😭）
- **誤訳**: 草 → "grass"、💀 →「死」「不吉」、🙏 →「祈り／許しを請う」
- **本来**: 草＝www（笑）の視覚化。💀＝英語圏では**爆笑**（"I'm dead"）。🙏は日本ではありがとう／お願い、中国語圏では祈り。😭＝ファンダムでは**感動の号泣＝ポジティブ**
- **壊れるもの**: 記号は翻訳器の対象外なので**素通り**するが、**受信側の文化コードで再解釈される**。「かわいすぎ💀」が「死ね」に読まれる事故は実在する。翻訳の失敗ではなく**翻訳の不在**による失敗という点で既存MTの構造的死角

## 後半：アイデア

### 1. OSHIGLOSS（推しグロス）— 三層グロス翻訳エンジン＋ブラウザ拡張
推し活投稿を「直訳／文化等価／熱量注釈」の3レイヤーで返す。他の全案の共通エンジンになる基盤。

**LLMの使い方（プロンプト設計）**
- 出力を強制JSON化：`{literal, natural, intensity(1-5), register, preserved_terms[], footnote, risk_flags[]}`
- **「訳さない判断」を最重要タスクとして明示**：「`oshi`, `ita-bag`, `bias` のように既に借用語として流通している語は翻訳せず原語＋短い注で残せ」。ここを指示しないとLLMは親切に訳してしまう
- **極性ガード**：「しんどい・無理・死ぬ・やばい・草・awsl・I'm dead・💀 の類は、文脈上ポジティブの可能性を第一候補として検討し、intensity を必ず出力せよ」を独立ルールとして置く
- **RAG**：用語集を**ベクトル＋完全一致のハイブリッド検索**で引き、ヒットした語だけを few-shot に動的注入。全語彙をプロンプトに詰めない
- **バックトランスレーション自己批評**：訳文を原言語に戻し、極性・register・intensity が保存されているかを別コールで採点、閾値割れなら再生成（1ループのみ）。**デモで「MTはここで壊れる、うちは戻ってくる」を可視化できるのが強い**
- 温度は低め（0.2前後）、ただし「文化等価」レイヤーだけ高め（0.8）で候補3つ出させて選ばせる

**48h MVP**：Chrome拡張（MV3）＋ Next.js API ルート＋ Claude API。用語集は200語の手書きYAML＋SQLite FTS で十分（**ベクトルDBは48hでは過剰**）。デモ用に既存MTの訳との左右比較トグルを必ず付ける。
**デモ映え ★★★☆☆**（比較トグルがあれば★4。単体だと「良い翻訳ツール」で終わりやすい）

### 2. FANDOM CUSTOMS（ファンダム入国審査）— 越境マナー翻訳＆投稿前ファイアウォール
投稿内容が「相手国のファンダム規範でどう読まれるか」を事前に警告し、衝突の起きない言い換えを提示する。

**壊す壁**：語彙ではなく**規範（暗黙のルール）の壁**。同担拒否、ネタバレ許容範囲、リプライしていい距離感、二次創作のCW文化、アイドルへの言及の距離感。国ごとに全部違う。

**LLMの使い方**
- コアは「**文化ペルソナ・パネル**」：単一評価ではなく `JP同人圏`, `EN Tumblr/AO3圏`, `KR ファンカフェ圏`, `CN 微博超话圏` の4ペルソナに**同じ投稿を並列で読ませ**、各々の視点で「どう読めるか／何が引っかかるか」を書かせる。並列コールがそのままデモの見せ場になる
- 各ペルソナのシステムプロンプトに**規範カード**（10〜15個の箇条書き規範＋実例）を埋め込む。**ここの質が製品の質**。例：EN圏ペルソナには「無警告のネタバレ・無タグのセンシティブ描写は倫理違反として扱われる」「"wrong"という語は解釈の押し付けと読まれる」
- 出力は**信号機**：🟢問題なし／🟡誤読リスク（理由＋言い換え案3つ）／🔴炎上リスク（該当箇所ハイライト＋文化的背景を2文で）
- **説教しないトーン制約を強く入れる**：「あなたは検閲官ではなく通訳者である。相手文化を『正しい』とせず、双方の前提の違いだけを述べよ」。ここを外すと即座に上から目線の説教botになり、ファンから嫌われる
- 応用：口論スレッドを貼ると**双方の言い分を互いの文化語彙で言い直す「調停モード」**。「彼女は非難していない、『解釈違い』は非難回避の語です」と割って入る

**48h MVP**：Web ＋ 貼り付け or 拡張。Discord bot 版（`/check`）だと越境サーバーで即実用。規範カードは4文化 × 12項目を手書きで用意（**ここに人手を全振り**）。
**デモ映え ★★★★★**（4文化が並列に反応する画面＋🔴警告は絵として強い）

### 3. WORLD PENLIGHT — 多言語同時視聴の熱量字幕＆コール翻訳
- ASR → LLM で**発話の機能ラベル**（MC雑談／煽り／感謝／重大発表／泣き）を付与し、字幕の色と大きさを機能で変える＝**熱量の視覚翻訳**
- コールは辞書＋LLMで「意味＋いつ叫ぶか＋ローマ字読み」を出し、**コール譜面**（カラオケ式）として表示。海外ファンが一緒に叫べるのが体験のコア
- 遅延対策：**頻出感嘆詞100語は事前翻訳済み辞書で0msヒット**させるのが実装上の肝
- **48h MVP**：実配信は不確実なので**収録済み映像を「疑似ライブ」として再生**するのが安全
- **デモ映え ★★★★★**（技術リスク最大）

### 4. FANSUB CO-PILOT — 有志翻訳のための用語集ガバナンス基盤
LLMが下訳、人間が監修、**議論の結果が用語集に還る**協働エディタ。

- 下訳時に用語集を強制注入し、**「用語集にない固有表現を検出したら訳さず `⚠️未登録` として提案キューに送れ」**を必須ルールに。**翻訳の網羅より未知語の発見をLLMの主タスクにするのが設計の肝**
- 用語エントリをLLMに起草させ（`{原語, 訳語候補3, 語源, 使用文脈, 感情極性, 訳さない方が良いか, 出典例文}`）、人間は◯×を押すだけ＝**レビュー負荷を承認1クリックまで下げる**
- 差分学習：監修者が訳を直したら diff をLLMに読ませ「一般ルールか、この文脈限定か」を判定させ、一般ルールならスタイルガイドに1行追記を提案。**育つ翻訳メモリ**
- 権利面の逃げ道として、対象を「公式の許諾があるもの／CC素材／ファン自身の投稿・ファンレター」に限定した設計にしておくと審査で強い
- **デモ映え ★★★☆☆**（地味だが実運用の説得力・社会的意義は7案中トップクラス）

### 5. TAG BRIDGE — 二次創作タグの越境橋渡し＆地雷フィルタ
pixivのタグとAO3のタグを相互変換し、「自分の地雷」を宣言すれば**どの言語圏の作品でも事前に遮断**する。

**壊す壁**：**警告文化の非対称**。EN圏はCW/タグ倫理が極めて厳格、JP圏は「※注意書き」文化、CN圏はまた別。タグが翻訳されないため、**警告が国境で失効する**。これは快適さの問題ではなく安全の問題。

- タグの**意味論マッピング**：`地雷` → 文脈で `squick` / `NOTP` / `hard no` / `menhera aesthetic` に分岐。1対1ではなく**1対Nの条件付き写像**をLLMに判定させる（前後のタグ列を全部渡すのが精度の鍵）
- 「自分の地雷」を自然文で登録できる → LLMが**タグ集合＋意味的クエリ**に変換し、多言語作品の説明文をスコアリングして遮断
- **CW自動起草**：日本語作品の本文から、EN圏基準で必要な警告タグ群を提案
- **安全側バイアスを明示**：「判断に迷う場合は必ず警告する側に倒せ」。フィルタは**偽陰性が致命的**であることをプロンプトに書く
- **48h MVP**：規約に注意し、**ダミーの作品メタデータ200件を自作**してデモするのが現実的（正直に言えばむしろ好印象）
- **デモ映え ★★★★☆**

### 6. CROSS-BORDER CAMPAIGN KIT — 越境動員の文言ローカライザ
署名・募金・ハッシュタグ運動・要望書を、**各国ファンダムが動く言い方**に翻訳する。

**壊す壁**：**動員の壁**。日本語圏の呼びかけをそのまま英訳しても海外ファンは動かない。**呼びかけの文法（何をどの順で言うか、どこまで押すか、どう信頼を担保するか）が文化ごとに違う**から。

- 単なる翻訳ではなく「**再設計**」を指示：「原文の情報を訳すのではなく、目的（署名を集める）を達成する現地版コピーをゼロから書け。原文は要件定義書として扱え」。**これが本案の核**
- 文化別の**呼びかけ規範カード**：JP＝控えめ・「参加は自由です」の明記／EN＝目的とインパクトを冒頭、明確なCTA、会計公開への言及／KR＝ファンカフェ告知フォーマット／CN＝超话内ルールと超短文＋画像
- **アカウンタビリティ文の自動生成**：募金系は「集金・使途・報告」の透明性文を各国規範で必須生成。**これが無いと海外では詐欺扱いされる**という知見をプロンプトに埋め込む
- **デモ映え ★★★★☆**

### 7. MISTRANSLATION FIRE ALARM（誤訳火災報知器）
誤訳が原因で燃え始めた越境炎上を検知し、「**元の発言は本当はこう言っている**」という反証カードを多言語で即座に生成・配布する。

- **原文サルベージ**：拡散している訳文から原文候補を特定し、**逐語アラインメント**。「どの語がどう変質したか」を `ニュアンス落ち / 極性反転 / 敬語落ち / 冗談の平叙化 / 主語補完の誤り` の5類型に分類
- **反証カードの自動生成**：原文引用＋逐語対照＋2文の解説＋文化注を4言語で。**画像カード**として出す（スクショで拡散されるのがSNSの現実だから）
- **煽らないトーン制約が生命線**：「誤訳を広めた個人を特定・非難してはならない。訂正は事実の提示のみで行い、相手の面子を潰す表現を使うな」。ここを外すと火消しツールが**新しい炎上装置**になる
- **不確実性の強制表明**：原文が特定できない場合は「未確認」と明示し断定させない。**ハルシネーションが最も危険なプロダクト**なので `confidence` フィールド必須＋低信頼時は生成拒否
- **48h MVP**：**手動トリガ版に絞る**（訳文を貼る → 原文を貼る → 誤訳診断カード）。検知の自動化は将来構想として語る
- **デモ映え ★★★★★**

## 推し案トップ2

**1位：CROSS-BORDER CAMPAIGN KIT** — ①テーマへの回答が最も直球。他案は「摩擦を減らす」＝守りだが、これは**熱量を実際の行動に変換する装置**で、問いに正面から Yes と答える ②**「翻訳」を再設計として捉え直した点がLLMでしか成立しない**。DeepLは呼びかけ文を訳せても、EN圏で機能する呼びかけに書き直すことはできない ③ステートレスな生成1本＋良いUIで成立し、リアルタイム性もデータ収集も不要。**技術リスクが低く、その分プロンプト（規範カード）の作り込みに全時間を投下でき、差がつくのが「文化知の質」になる**。

**2位：FANDOM CUSTOMS** — ①前半の分析（同担拒否・解釈違い・地雷）が最も直接プロダクト化される。**語彙ではなく規範の非対称こそが越境ファンダムの真の国境である**、という洞察が中核にあり着眼点が被りにくい ②**4文化ペルソナの並列評価**という見せ方が、LLMの得意領域（多視点シミュレーション）とデモ映えを同時に取る ③#1のエンジンを内包でき、**#6と組み合わせると「衝突を避けつつ動員する」一つの物語になる**。実際、**#6を本体、#2を投稿前チェック機能として同梱するのが最強の構成**だと思う。

**補足**：#7 は単体のインパクトでは最強だが、ハルシネーションが即座に実害（誤った「訂正」の拡散）になるため、48hプロトタイプで責任を持って出すには覚悟が要る。やるなら手動トリガ＋信頼度表示＋「参考情報」の明示を絶対条件に。
